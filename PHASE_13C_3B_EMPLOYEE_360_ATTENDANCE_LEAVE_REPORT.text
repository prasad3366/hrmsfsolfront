PHASE 13C-3B - EMPLOYEE 360 ATTENDANCE + LEAVE REPORT

Scope
-----
Implemented only Attendance and Leave in the existing EmployeeProfile Employee 360 tabs. Personal, Employment, and Contact sections remain available and unchanged in their displayed fields. Hierarchy, Assets, Documents, Payroll, and Performance were not added.

Exact files changed
-------------------
- src/modules/employees/EmployeeProfile.tsx
- src/services/api.ts
- PHASE_13C_3B_EMPLOYEE_360_ATTENDANCE_LEAVE_REPORT.text

APIs used
---------
Attendance:
- ApiService.getEmployee360Attendance(Number(employee.id), selectedMonth)
- GET /employees/:id/360/attendance?month=YYYY-MM

Leave:
- ApiService.getEmployee360Leave(Number(employee.id))
- GET /employees/:id/360/leave

No broad employee API, organization-wide leave API, teamId, managerId, or alternate employee identity is used for these sections. Backend remains the authorization authority.

UI sections added
-----------------
- Attendance tab.
- Leave tab.
- Existing Personal, Employment, and Contact tabs remain present with Personal still the default.

Attendance behavior
-------------------
- Defaults to the current month using the existing application month-input convention.
- Selecting another month requests the selected YYYY-MM value from the safe 360 attendance method.
- Fetching is scoped to the displayed employee ID from the safe profile response.
- Displays only backend-provided summary values:
  - month
  - working days
  - present days
  - half days
  - leave days
  - absent days
  - present equivalent days
  - attendance percentage
- Does not render raw attendance records, timestamps, punch locations, coordinates, latitude/longitude, device metadata, or geolocation data.
- States are distinct: loading, API error, no summary, and successful summary.
- No attendance calculations are performed in the frontend.

Leave behavior
--------------
- Loads the target employee through the safe 360 leave method when the Leave tab is selected.
- Displays only safe summary/projection fields returned by the backend:
  - current leave status
  - total, pending, approved, and rejected request counts
  - balance summary: leave type, allocated, used, and remaining values
  - recent leave metadata: leave type, status, and total days
- Does not render leave reasons, medical certificate content, medical details, raw confidential data, or raw leave records.
- States are distinct: loading, API error, no leave information, and successful safe summary.
- No leave calculations are performed in the frontend.

API typing changes
------------------
- Employee360Attendance is now typed for the eight backend summary values.
- Employee360Leave is now typed for the safe summary object: currentLeaveStatus, balanceSummary, leaveCounts, and recentHistory.
- Existing shared authenticated GET/error handling remains in use.

Preserved functionality
-----------------------
- Existing EmployeeProfile route and self/target behavior remain unchanged.
- Existing safe base profile load remains GET /employees/:id/360.
- Existing detailed getEmployeeById() load remains exclusively behind the Edit action.
- Existing Edit behavior and Give Raise behavior remain unchanged.
- No frontend-only authorization rules were added.
- No sensitive payroll, banking, identification, document-file, or asset UI was added.
- Performance remains deferred.
