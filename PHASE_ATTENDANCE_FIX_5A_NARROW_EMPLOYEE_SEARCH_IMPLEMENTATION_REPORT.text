Exact implementation
--------------------

EmployeeAttendance now:
- Reads the current searchTerm and trims it before querying.
- Does not request an employee directory when the search is empty.
- Calls the existing method with exactly the supported query fields:
  - search: trimmed searchTerm
  - page: 1
  - pageSize: 25
- Reads employee rows from response.data using the existing
  EmployeeDirectoryResponse shape.
- Keeps the existing employee object fields used by the UI: id,
  firstName/lastName or name fallback, empCode, and designation.
- Preserves the existing result-row selection behavior.
- Preserves the selected-employee calls for target attendance, attendance
  summary, and Employee 360 leave without modification.

Bounded page size
-----------------

The selector uses pageSize 25. It does not use 10000 or an unbounded value.
No pagination UI was added because the existing selector UX is preserved with
the first bounded server-result page.

Search behavior
---------------

Before this change, EmployeeAttendance loaded the unqueried GET /employees
collection once and filtered that loaded array locally.

After this change, a non-empty searchTerm drives:

- GET /employees?search=<searchTerm>&page=1&pageSize=25

The returned response.data rows are displayed directly. Empty search results
continue to show the existing no-match state. Query failures continue to set
the existing error state and are not silently converted into an empty result.

The target report workflow remains unchanged: selecting a result still uses
the selected employee's id for the existing target attendance, monthly
summary, and Employee 360 leave requests.

Authorization and request inputs
--------------------------------

No frontend authorization logic was added. The request sends no role,
managerId, teamId, or impersonating employeeId. The selected employee id is
used only as the resource id for the existing authorized target requests.
Backend authorization remains authoritative for SUPER_ADMIN, CEO, HR,
FINANCE_MANAGER, IT_MANAGER, SALES_MANAGER, and EMPLOYEE behavior.

No broad unqueried Attendance request remains

and pageSize. Other unrelated frontend modules may still call the shared API
method for their own workflows; they were outside this phase and were not
changed.
