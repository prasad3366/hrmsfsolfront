API methods added
-----------------
ApiService now provides typed, authenticated GET methods for:

- getEmployee360(employeeId) -> GET /employees/:id/360
- getEmployee360Attendance(employeeId, month) -> GET /employees/:id/360/attendance?month=YYYY-MM
- getEmployee360Leave(employeeId) -> GET /employees/:id/360/leave
- getEmployee360Hierarchy(employeeId) -> GET /employees/:id/360/hierarchy
- getEmployee360Assets(employeeId) -> GET /employees/:id/360/assets
- getEmployee360Documents(employeeId) -> GET /employees/:id/360/documents
- getEmployee360Payroll(employeeId) -> GET /employees/:id/360/payroll

Implementation details:
- All methods use the existing API base URL, getAuthHeaders(), native fetch, GET, response.ok checks, and existing Error propagation style.
- The attendance month is URL encoded.
- A shared private getEmployee360Resource<T>() helper avoids duplicate request/error logic.
- Typed response interfaces were added for the 360 profile, hierarchy, assets, documents, payroll, leave, and attendance responses.
- No client-supplied role, teamId, or managerId is used for authorization decisions.
- No legacy fallback is used inside the new 360 methods.

EmployeeProfile.tsx changes
---------------------------
- Initial profile loading now calls ApiService.getEmployee360(Number(id)) instead of getEmployeeById() and therefore uses the safe 360 profile projection.
- Asset loading now calls ApiService.getEmployee360Assets(Number(employee.id)) instead of getMyAssetsByUserId(), avoiding the broad GET /assets plus frontend filtering path for the profile asset section.
- Existing profile UI, loading/error behavior, asset empty/error behavior, edit action, Give Raise action, and role gating remain in place.
- To preserve the existing edit form's complete field population, the broad getEmployeeById() call is deferred to the existing Edit action only. It is not used for the initial 360 profile read or 360 asset data.
- No tabs, new UI sections, Performance, or unrelated profile refactoring were added.
