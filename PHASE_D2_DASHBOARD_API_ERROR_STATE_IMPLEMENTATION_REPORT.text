Behavior changed
----------------

Existing Dashboard API errors now produce an explicit dashboard-level error
banner while preserving the existing card structure and successful rendering.
The error state covers the Dashboard-owned employee requests and the existing
hook errors consumed by the Admin, HR, and Manager dashboards.

The Manager dashboard no longer replaces failed employee data with
MOCK_EMPLOYEES or derives task/employee metrics from that fallback. Its affected
metrics show Error and the employee-dependent performance section does not
fall back to mock data after an API failure.

Successful responses remain unchanged. Existing loading states and D1 role
routing/visibility remain unchanged.

- AdminDashboard: getAllEmployees(), fetchAllWfhRequests(), usePayroll data.
- HRDashboard: getAllEmployees(), getHelpdeskTickets(), fetchAllWfhRequests(),
  fetchPendingLeaves(), and useAttendance({ scope: 'all' }).
- ManagerDashboard: getAllEmployees(), fetchAllWfhRequests(),
  fetchPendingLeaves(), and useAttendance({ scope: 'all' }).
- EmployeeDashboard continues to use its existing hooks and was not modified
  because it already exposes loading/error behavior through its existing child
  sections; no unrelated Dashboard redesign was introduced.
